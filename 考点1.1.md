# 1. 最高概率：C memory bugs + pointer reasoning

<a id="p1-1"></a>
## 1.1 为什么这个方向最稳

5 份 PPT 中 Week 1-3 很大篇幅都在铺 C memory model：

- array bounds not checked
- undefined behaviour
- pointer stores address
- pointer type affects dereference and arithmetic
- stack / heap / data / text
- malloc/calloc/realloc/free
- string buffer overflow
- linked list with strings

三份试卷又反复用 C 代码找错的方式考这些能力。

所以预测不是“还会考同一段 linked list/tree 代码”，而是：

```text
还会考你能不能根据 C memory model 找出 undefined behaviour / memory leak / dangling pointer / wrong free / buffer overflow。
```

---

<a id="p1-2"></a>
## 1.2 预测会考的能力，而不是具体题

最可能考这些能力：

### 1. Stack object 不能返回地址

```c
struct Node newNode;
return &newNode;  // wrong
```

高分解释：

```text
newNode is a local variable stored in the stack frame. After the function returns, the stack frame is invalid, so the returned pointer becomes dangling.
```

### 2. 先 free 再访问

```c
free(node);
node = node->next;  // wrong
```

解释：

```text
After free(node), the program no longer owns that memory. Accessing node->next is use-after-free and causes undefined behaviour.
```

### 3. free 非 heap memory

```c
free(node->value);  // wrong if value is int
```

解释：

```text
free must only be called on pointers returned by malloc/calloc/realloc. If value is an int, it is not dynamically allocated memory.
```

### 4. malloc 后没有检查 NULL

```c
Node *p = malloc(sizeof(Node));
p->next = NULL;   // risky if p == NULL
```

解释：

```text
If malloc fails and returns NULL, dereferencing p causes a crash. The result of dynamic allocation should be checked before use.
```

### 5. string arbitrary length 不能塞进 fixed buffer

```c
char title[80];
strcpy(title, newTitle);  // unsafe if newTitle is arbitrary length
```

解释：

```text
strcpy does not check the destination size and copies the terminating null byte too, so a long source string can overflow the destination buffer.
```

---

<a id="p1-3"></a>
## 1.3 答题时优先检查清单

考试看到 C 代码，先按这个顺序扫：

```text
1. 有没有返回 local variable 地址？
2. 有没有 free 后继续访问？
3. 有没有 double free？
4. 有没有 free 不是 malloc/calloc/realloc 得来的地址？
5. malloc/calloc/realloc 有没有 NULL check？
6. strcpy/strcat/scanf("%s") 有没有 buffer overflow？
7. linked list 删除时有没有先保存 next？
8. 指针类型是否匹配？二维数组是否把 a 当 int*？
9. 函数是否只是改 copy，没有改 caller 的对象？
10. return 前有没有漏 free 或漏 unlock？
```

预测权重：`⭐⭐⭐⭐⭐`

# 2. 最高概率：Thread safety / race condition / mutex

<a id="p2-1"></a>
## 2.1 不 overfit 的预测逻辑

Week 4 和 Week 5 进入 threads 后，核心就变成：

```text
shared data + concurrent access + unpredictable interleaving
```

历年可能用 stack、request queue、linked list、tree、server、booking system 来包装，但本质一样：

- 找 shared data。
- 找 critical section。
- 加 mutex 或更合适的 lock。
- 尽量不牺牲 parallelism。

---

<a id="p2-2"></a>
## 2.2 可能出现的外壳

不要只背某一道题的代码，要会迁移到这些外壳：

| 外壳 | Shared data | 可能问题 |
|---|---|---|
| stack | `count`, `values[]` | push/pop 同时改 count |
| queue | `head/tail/count`, array/list | lost update, overflow/underflow |
| linked list | `head`, nodes | insert/delete/member 并发出错 |
| tree | node children pointers | alloc/delete 并发访问同一 subtree |
| server | request list / client list | 多 client worker 同时改共享结构 |
| booking system | seats/meals counters | check-then-act race |

---

<a id="p2-3"></a>
## 2.3 高分答题结构

如果题目问：Is it thread-safe? How to fix?

答题结构：

```text
1. It is not thread-safe because multiple threads may access and modify shared state concurrently.
2. The shared state is ...
3. The critical section is ...
4. Protect the critical section with the same mutex.
5. To maximise parallelism, keep non-shared or slow operations outside the lock.
```

代码模板：

```c
pthread_mutex_lock(&m);
// only shared data access/modification here
pthread_mutex_unlock(&m);
```

如果有 early return：

```c
pthread_mutex_lock(&m);
if (error) {
    pthread_mutex_unlock(&m);
    return -1;
}
pthread_mutex_unlock(&m);
```

预测权重：`⭐⭐⭐⭐⭐`

<a id="p3"></a>
# 3. 很高概率：Condition variable / producer-consumer 变体

<a id="p3-1"></a>
## 3.1 为什么 week5 很值得押

Week 5 开头用很多页讲 condition variable，而且这类题非常适合考试，因为它能同时考：

- mutex
- wait/signal
- shared condition
- missed wake-up
- `while` vs `if`
- producer-consumer / bounded buffer

---

<a id="p3-2"></a>
## 3.2 不要背 count 例子，要背模型

模型：

```text
Thread A waits until condition C becomes true.
Thread B changes shared data so C may become true, then signals.
```

标准代码：

```c
pthread_mutex_lock(&m);
while (!condition) {
    pthread_cond_wait(&cond, &m);
}
// use the resource/state
pthread_mutex_unlock(&m);
```

signal side：

```c
pthread_mutex_lock(&m);
// change shared state
pthread_cond_signal(&cond);
pthread_mutex_unlock(&m);
```

最可能被问的解释：

### 为什么 `pthread_cond_wait` 要 mutex？

```text
Because checking the condition and going to sleep must be coordinated with updates to the condition. pthread_cond_wait atomically releases the mutex and puts the thread to sleep, then reacquires it before returning.
```

### 为什么 `while` 不用 `if`？

```text
Because a wake-up only means the condition may have changed. The thread may wake spuriously, or another thread may consume the condition before it reacquires the mutex.
```

预测权重：`⭐⭐⭐⭐⭐`

<a id="p4"></a>
# 4. 很高概率：Read-write lock / linked list parallelism

<a id="p4-1"></a>
## 4.1 预测依据

Week 5 后半部分明显在铺一个考试味很重的问题：

```text
shared sorted linked list + Member/Insert/Delete + multiple threads
```

它比普通 mutex 更适合考“maximise parallelism”。

因为：

- `Member()` 是 read-only。
- `Insert()` / `Delete()` 是 write。
- 多个 readers 同时读是安全的。
- writer 必须独占。

---

<a id="p4-2"></a>
## 4.2 出题方式预测

可能问法：

```text
A shared linked list is accessed by many threads. Most operations are Member operations, with occasional Insert/Delete. Compare using a single mutex, fine-grained node locks, and read-write locks.
```

高分答案：

```text
A single mutex is simple and correct but serializes all operations, so it wastes parallelism when many operations are reads. Fine-grained node locking can increase parallelism but makes the code complex and may add overhead or deadlock risks. A read-write lock is a good compromise for read-heavy workloads because it allows multiple Member operations to run concurrently while Insert/Delete obtain exclusive access.
```

预测权重：`⭐⭐⭐⭐⭐`

<a id="p5"></a>
# 5. 高概率：`pthread_create` 参数传递 + `pthread_join`

这个点历年考过，但不代表只是旧题。它背后的稳定能力是：

```text
thread function takes void* argument, and thread scheduling is nondeterministic
```

最常见错误：

```c
for (int i = 0; i < 10; i++) {
    pthread_create(&tid, NULL, f, &i);
}
```

预测可能换成：

- 给每个 thread 一个 id。
- 给每个 thread 一个 array index。
- 给 worker 传 struct argument。

正确原则：

```text
Each thread must receive a pointer to storage that remains valid and is not overwritten before the thread reads it.
```

推荐模板：

```c
pthread_t tids[N];
int args[N];

for (int i = 0; i < N; i++) {
    args[i] = i;
    pthread_create(&tids[i], NULL, worker, &args[i]);
}

for (int i = 0; i < N; i++) {
    pthread_join(tids[i], NULL);
}
```

`join` 高分解释：

```text
pthread_join waits for a thread to terminate. It is useful for ordering, but it does not by itself prevent race conditions on shared data.
```

预测权重：`⭐⭐⭐⭐`

<a id="p6"></a>
# 6. 中高概率：String / buffer overflow / safe string functions

Week 2 的 string 内容和 C memory bug 高度绑定。

最可能问：

1. 为什么 `strcpy` 危险？
2. `strlen` 有没有包括 `\0`？
3. `char str[7] = "Comp Sc";` 够不够？不够，因为还要 `\0`。
4. `scanf("%s", str)` 有什么风险？不限制长度。
5. `strncpy` 为什么还要手动补 `\0`？

答题模板：

```text
C strings are arrays of characters terminated by '\0'. The programmer must allocate enough memory for all characters plus the terminator. Functions such as strcpy and scanf with %s do not automatically check the destination size, so they may cause buffer overflow.
```

预测权重：`⭐⭐⭐⭐`

<a id="p7"></a>
# 7. 中概率：2D array、void pointer、function pointer

这三个点都适合出小问。

## 7.1 2D array

高概率小问：

```c
int a[3][4];
int *p = a;        // why warning?
int *q = &a[0][0]; // why better?
```

答案：

```text
In a 2D array, a is the address of the first row, not a pointer to a single int. &a[0][0] is the address of the first int element.
```

## 7.2 void pointer

可能问：为什么 `pthread_create` 的 argument 是 `void*`？

答案：

```text
void* is a generic pointer type, so the thread function can receive a pointer to any kind of data. Inside the function it must be cast back to the correct type before dereferencing.
```

## 7.3 function pointer

可能作为 callback 背景。

低于 memory/thread，不建议重押。

预测权重：`⭐⭐⭐`

# 9. 中概率：Sockets + sequential vs concurrent server

Week 4 开头讲 sockets，但后面马上引出 concurrent server 和 threads，所以真正考点不是背 socket API，而是：

```text
为什么 sequential server 不适合多个 clients？为什么 concurrent server 更 responsive？
```

可能问：server 和 client 初始化区别。

Server：

```text
socket → bind → listen → accept → read/write → close
```

Client：

```text
socket → connect → read/write → close
```

Sequential server 问题：

```text
A slow or buggy client may block the server, preventing later clients from being served.
```

Concurrent server：

```text
A server can create a new thread/process per client so multiple clients are handled concurrently.
```

预测权重：`⭐⭐⭐`

# 10. 低到中概率：architecture / multicore 背景

这些内容一般不会作为大题核心，但可能作为理解题。

## 10.1 Von Neumann

```text
Instructions and data are stored in memory, and the CPU repeatedly fetches, decodes and executes instructions.
```

## 10.2 Register / cache / memory / disk

可能问：为什么 cache 有用？

```text
Because memory and disk accesses are much slower than register/cache accesses, systems exploit locality by keeping recently used data in faster storage.
```

## 10.3 Multicore

可能问：为什么现代系统需要 concurrent programming？

```text
Because performance improvements increasingly come from using multiple cores rather than simply increasing clock frequency.
```

## 组合 2：multi-threaded server + shared queue + condition variable

可能题目：server 有 producer 接收 request，worker threads 消费 request。

考点混合：

```text
socket/concurrent server background
bounded buffer
mutex
condition variables
while loop
not_empty / not_full
```

推荐模型：

```c
while (queue_empty) pthread_cond_wait(&not_empty, &m);
while (queue_full) pthread_cond_wait(&not_full, &m);
```

可能题目：很多 threads 查找，少数 insert/delete。

考点混合：

```text

```

# 12. 考前最后押题清单

## 12.1 必须会写的代码模板

### Mutex

```c
pthread_mutex_lock(&m);
// critical section
pthread_mutex_unlock(&m);
```

### Early return

```c
pthread_mutex_lock(&m);
if (error) {
    pthread_mutex_unlock(&m);
    return -1;
}
pthread_mutex_unlock(&m);
```

### Condition variable

```c
pthread_mutex_lock(&m);
while (!condition) {
    pthread_cond_wait(&cond, &m);
}
// use shared state
pthread_mutex_unlock(&m);
```

### Read-write lock

```c
pthread_rwlock_rdlock(&lock);
// read only
pthread_rwlock_unlock(&lock);

pthread_rwlock_wrlock(&lock);
// modify
pthread_rwlock_unlock(&lock);
```

### pthread_create safe argument

```c
pthread_t tids[N];
int args[N];
for (int i = 0; i < N; i++) {
    args[i] = i;
    pthread_create(&tids[i], NULL, worker, &args[i]);
}
for (int i = 0; i < N; i++) {
    pthread_join(tids[i], NULL);
}
```

## 12.2 必须背熟的英文句子

```text
C passes arguments by value, so modifying a parameter only modifies the local copy.
```

```text
A race condition occurs when the result depends on the timing or interleaving of concurrent operations on shared data.
```

```text
pthread_join waits for a thread to terminate, but it does not protect shared data from concurrent access.
```

```text
A condition variable must be used with a mutex because checking the condition and going to sleep must be coordinated atomically.
```

```text
A read-write lock allows multiple readers to access shared data concurrently while writers require exclusive access.
```

```text
After free(p), the memory is no longer owned by the program, so accessing it causes undefined behaviour.
```

```text
strcpy does not check the destination buffer size and may cause buffer overflow.
```
