# Part A - C Programming and Memory Safety

## 1. Pointers

### Definition to memorise

A **pointer** is a variable whose value is the memory address of another object.

中文理解：**pointer** 是一个变量，但它存的不是普通数值，而是另一个 object 在 memory 里的 address。

```c
int a = 5;
int *p = &a;   // p stores the address of a
*p = 10;       // dereference p and modify a
```

### Key facts

- `&x` means “address of x”。
- `*p` means “the value stored at the address held by p”。
- pointer 有 type，例如 `int *`, `char *`, `struct node *`。
- pointer type 很重要，因为它决定 C 读/写多少 bytes，以及 pointer arithmetic 如何移动。

### Exam answer: how pointers can return several values

C function normally returns one value。想要“返回多个值”，可以把变量的 pointer 传进去，让 function 通过 pointer 修改 caller 的 memory。

```c
void divmod(int a, int b, int *q, int *r) {
    *q = a / b;
    *r = a % b;
}
```

这不是 function 直接 return 两个 values，而是它修改了 caller 提供的 memory locations。

### Common dangers

| Problem | Meaning | Consequence |
|---|---|---|
| Uninitialised pointer | pointer 里是 garbage address | crash 或 memory corruption |
| Dangling pointer | pointer 指向 invalid / freed / local memory | undefined behaviour |
| Wrong type cast | memory 被当成错误 type 解读 | wrong values, crashes, corruption |
| Out-of-bounds pointer arithmetic | address 超出 object 范围 | undefined behaviour |

## 2. Arrays and Pointer Arithmetic

### Definition to memorise

An **array** is a fixed-size sequence of elements of the same type stored contiguously in memory.

中文理解：**array** 是一段连续 memory，里面放同一种 type 的 elements，大小固定。

```c
int a[10];
```

- `a` often behaves like a pointer to `a[0]`。
- `a + i` points to element `a[i]`。
- `*(a + i)` is equivalent to `a[i]`。

### Pointer arithmetic

**Pointer arithmetic** moves by elements, not bytes。

如果 `p` 是 `int *`，那么 `p + 1` 指向下一个 `int`，通常是 4 bytes 后，而不是 1 byte 后。

### 2D arrays

C stores 2D arrays in **row-major order**：

1. row 0 的所有元素先存；
2. 然后 row 1；
3. 继续往后。

```c
int a[3][4];
```

- `a` is not an `int *`；它更接近“指向一整 row 的 pointer”。
- `&a[0][0]` is an `int *` pointing to the first integer。

### Common exam trap

```c
int a[3] = {1, 2, 3};
sum = a[1] + a[2] + a[3];
```

`a[3]` is out of bounds。合法 indexes 是 `0, 1, 2`。读 `a[3]` 是 **undefined behaviour**。

## 3. Strings in C

### Definition to memorise

A C string is a sequence of characters stored in a `char` array and terminated by the null character `\0`.

中文理解：C 里的 **string** 本质上是 `char` array，最后必须有 `\0` 表示结束。

```c
char s[] = "CompSc";
```

Memory contains：

```text
C o m p S c \0
```

length 是 6，但 array 需要 7 个 characters，因为还要存 `\0`。

### Important string functions

| Function | Purpose | Danger |
|---|---|---|
| `strlen(s)` | length excluding `\0` | 需要 valid null-terminated string |
| `strcpy(dst, src)` | copies string including `\0` | 不检查 destination size |
| `strcat(dst, src)` | appends `src` to `dst` | 可能 overflow `dst` |
| `strcmp(a,b)` | compares strings | equal 时 returns 0 |
| `strncpy`, `strncmp`, `strncat` | bounded versions | 仍然需要小心 |

### Buffer overflow

A **buffer overflow** occurs when a program writes more data into a buffer than it can hold.

危险原因：

- overwrites nearby memory；
- can corrupt variables, pointers, stack frames, or return addresses；
- may cause a crash；
- may allow attackers to execute injected code。

### Exam phrase

C does not automatically check array/string bounds at runtime。Therefore, writing beyond the end of a character array may corrupt memory and lead to undefined behaviour or security vulnerabilities。

## 4. Local, Global, Static, Heap and Stack Variables

### Local variables

- Declared inside a function。
- Usually stored in the stack frame。
- Lifetime ends when the function returns。

### Global variables

- Declared outside functions。
- Exist for the whole program execution。
- Shared between functions；in multithreaded programs, shared between threads。

### Static variables

- Exist for the whole program execution。
- If inside a function, they keep their value between calls。
- In multithreaded code, static local variables can become shared state。

### Heap variables

- Allocated dynamically using `malloc`, `calloc`, `realloc`。
- Must be released using `free`。
- Lifetime continues until explicitly freed。

### Stack frame

A **stack frame** stores data for one function call, such as local variables, saved registers, return address, and parameters。

function call 时会 push 新 frame；function return 时 frame 被 destroyed。

### Returning pointer to local variable

Never return the address of a local variable：

```c
int *bad() {
    int x = 5;
    return &x;
}
```

function return 后，`x` 不存在了。返回的 pointer 是 **dangling pointer**。

## 5. Dynamic Memory Management

### Must know

- `malloc(size)` allocates uninitialised memory。
- `calloc(n, size)` allocates memory and initialises it to zero。
- `realloc(ptr, newSize)` changes the size of a previously allocated block。
- `free(ptr)` releases heap memory。

### `calloc`

`calloc` 常用于创建 array 或 struct，因为它会把 memory 清零。例如 tree/list node 用 `calloc` 后，pointers 通常会是 `NULL`。

### `realloc`

`realloc` 可能在原位置扩大，也可能搬到新地址。安全写法通常是先用 temporary pointer：

```c
int *tmp = realloc(p, newSize);
if (tmp != NULL) p = tmp;
```

如果直接 `p = realloc(p, newSize);`，失败时原来的 pointer 可能丢失，造成 **memory leak**。

### Memory leak

A **memory leak** occurs when dynamically allocated memory is no longer reachable and therefore cannot be freed。

系统编程里 memory leak 很严重，因为 long-running programs / kernel code 不退出，leaked memory 会一直被占用，最终可能导致 memory exhaustion。

### Double free

**Double free** means calling `free` twice on the same memory block。后果可能是 heap corruption, crash, undefined behaviour。

### Use-after-free

**Use-after-free** means accessing memory after it has been freed。后果是 undefined behaviour，也可能被 attacker 利用。

### Safe freeing linked structures

删除 linked list / tree 时，要先保存 next/children，再 `free` 当前 node，或者递归先删除 children 再删 parent。不能 `free(node)` 后再访问 `node->next` 或 `node->left`。

## 6. Segmentation Fault and Undefined Behaviour

### Segmentation fault

A **segmentation fault** occurs when a program tries to access memory that it is not allowed to access。

常见原因：

- dereferencing `NULL`；
- dereferencing an uninitialised pointer；
- accessing freed memory；
- accessing out-of-bounds memory；
- writing to read-only memory；
- stack overflow。

### Undefined behaviour

**Undefined behaviour** means the C standard gives no guarantee about what happens。

它危险是因为：

- program may appear to work；
- program may crash；
- compiler may optimise assuming it never happens；
- security vulnerabilities may appear；
- behaviour may change between machines or compiler versions。

Exam phrase：undefined behaviour must be avoided because once it occurs, the program has no reliable meaning.

---

## 7. Pass-by-Value and Pass-by-Reference Style in C

### Pass-by-value

C uses **pass-by-value**：function receives a copy of each argument。

```c
void f(int x) { x = 10; }
```

Changing `x` does not change caller's variable。

### Pass-by-reference style

C does not have true pass-by-reference like some languages, but you can simulate it by passing a pointer：

```c
void f(int *x) { *x = 10; }
```

Now the function can change caller's memory。

### Exam phrase

Arguments in C are passed by value. If an argument is a pointer, the pointer value is copied, but both the original pointer and the copied pointer can refer to the same memory object.

## 8. Command-Line Arguments

C program entry point can be：

```c
int main(int argc, char *argv[])
```

- `argc` = number of command-line arguments。
- `argv` = array of strings。
- `argv[0]` is usually the program name。
- `argv[1]`, `argv[2]`, ... are user-supplied arguments。

Example：

```bash
./program arg1 arg2 arg3
```

Then：

- `argc == 4`；
- `argv[0] == "./program"`；
- `argv[1] == "arg1"`；
- `argv[2] == "arg2"`；
- `argv[3] == "arg3"`。

Quoted arguments with spaces count as one argument：

```bash
./program "First argument" "Second argument"
```

## 9. Function Pointers and Void Pointers

### Function pointer

A **function pointer** stores the address of a function。

```c
int (*foo)(int arg);
```

This means `foo` is a pointer to a function taking `int` and returning `int`。

Compare：

```c
int *foo(int arg);
```

This means `foo` is a function taking `int` and returning `int *`。

Function pointers are useful for callbacks, event handlers, sorting comparison functions, and generic algorithms。

### Void pointer

A **void pointer** (`void *`) is a generic pointer type。It can point to data of any type, but must be cast back to the correct type before dereferencing。

Wrong cast is dangerous because C will interpret the same bytes as the wrong type。

Common use：`pthread_create` passes arguments as `void *`。

### Key ideas

- command lines tell `make` how to rebuild target。

- `CFLAGS=-Wall -Werror -g` sets compiler flags。

# Part B - Threads and Synchronisation

## 11. Purpose of Threads

### Definition to memorise

A **thread** is a separate path of execution within a process.

### Why use threads?

Threads allow concurrency inside one process。They are useful for responsiveness, parallelism on multicore systems, and overlapping computation with I/O。

### What threads share

Threads in the same process share：

- global variables；
- heap memory；
- open files；
- address space。

Each thread has its own：

- stack；
- registers；
- program counter。

Shared data means threads can interfere with each other, so synchronisation is needed。

---

## 12. Race Conditions

### Definition to memorise

A **race condition** occurs when the correctness of a program depends on the relative timing or interleaving of concurrent executions.

Example：`count++` is not a single atomic action。It may be compiled as：

1. load `count` into register；
2. add one；
3. store register back to `count`。

If two threads do this at the same time, updates can be lost。

### Exam phrase

A race condition occurs because multiple threads access shared data concurrently and at least one access modifies the data, without proper synchronisation.

---

## 13. Critical Section

### Definition to memorise

A **critical section** is a part of a program where shared data is accessed and where concurrent execution could lead to inconsistency.

Typical examples：

- modifying shared counter；
- modifying linked list / stack / queue；
- checking and updating seat booking data；
- reading shared data that must be consistent with another shared variable。

### Why keep critical sections short?

Critical sections should take as little time as possible because other threads may be blocked while waiting for the lock。Long critical sections reduce parallelism and performance。

### What if a thread blocks inside a critical section?

If a thread blocks while holding a lock, other threads needing that lock cannot proceed。This can cause poor performance, starvation, or deadlock-like behaviour。

---

## 14. Synchronisation Errors Are Hard to Find

### Memorise this answer

Synchronisation errors are difficult to find because they depend on timing and thread interleavings。A bug may appear only under specific scheduling decisions, CPU speeds, workloads, or numbers of cores。Adding debugging output can change timing and hide the bug。

Good exam wording：

They are often intermittent and non-deterministic, so the same program may work correctly many times and fail only rarely.

---

## 15. Mutexes

### Definition

A **mutex** is a mutual exclusion lock used to ensure that only one thread at a time executes a critical section.

Basic pattern：

```c
pthread_mutex_lock(&m);
/* critical section */
pthread_mutex_unlock(&m);
```

### Rules

- Use the same mutex for all access to the same shared data。
- Lock before reading/writing shared state。
- Unlock after the critical section。
- Keep the locked region as small as possible。
- Avoid blocking operations while holding the lock。

### Common exam issue

Using two different mutexes for the same shared data does not protect it correctly。All related accesses must use the same lock。

---

## 16. Condition Variables

### Definition

A **condition variable** allows a thread to wait until a condition on shared data becomes true.

### Key functions

- `pthread_cond_wait(&cond, &mutex)` waits and atomically releases the mutex while sleeping。
- `pthread_cond_signal(&cond)` wakes one waiting thread。
- `pthread_cond_broadcast(&cond)` wakes all waiting threads。

### Critical rule

Always use a `while` loop, not `if`：

```c
pthread_mutex_lock(&m);
while (!condition) {
    pthread_cond_wait(&cond, &m);
}
/* condition is true */
pthread_mutex_unlock(&m);
```

Reason：thread may wake up even if condition is no longer true, or another thread may consume the resource first。

### Why does `pthread_cond_wait` need a mutex?

The mutex protects the shared condition and prevents lost wakeups。`pthread_cond_wait` atomically releases the mutex and puts the thread to sleep, so another thread can change the condition and signal safely。

---

## 17. Semaphores

### Definition

A **semaphore** is a synchronisation primitive containing an integer counter, usually manipulated by wait/down and signal/up operations。

### Common use

Semaphores can count available resources, such as empty slots or full slots in a bounded buffer。

Producer-consumer often uses：

- `mutex` for mutual exclusion；
- `empty` counting empty buffer slots；
- `full` counting full buffer slots。

---

## 18. Critical-Section Solution Criteria

A correct critical-section solution should satisfy：

### 1. Mutual exclusion

At most one process/thread can be in the critical section at the same time。

### 2. Progress

If no one is in the critical section, processes that want to enter should be able to make progress；processes outside should not block them。

### 3. Bounded waiting

There must be a bound on how many times others can enter before a waiting process is allowed in。This prevents starvation。

---

## 19. Deadlock

### Definition

A **deadlock** occurs when a set of processes/threads are permanently blocked because each is waiting for a resource held by another.

### Four necessary conditions

1. Mutual exclusion。
2. Hold and wait。
3. No preemption。
4. Circular wait。

### Prevention idea

Break at least one of the four conditions, for example by imposing a global lock ordering to prevent circular wait。

# Part C - Operating System Foundations

## 20. What is an Operating System?

### Definition

An **operating system** is a program that acts as an intermediary between users/applications and computer hardware.

### Two main roles

1. **Resource allocator**：manages CPU, memory, devices, disk, and decides between conflicting requests。
2. **Control program / protection system**：controls execution to prevent errors and improper use of the computer。

---

## 21. Von Neumann Architecture

### Definition

A **stored-program computer** stores program instructions in memory, so reprogramming does not require hardware rewiring。

### Main components

- CPU；
- Memory；
- I/O interfaces。

### CPU components

- **Control Unit (CU)** controls instruction execution。
- **Arithmetic and Logic Unit (ALU)** performs arithmetic and logical operations。

### Why registers are useful

Registers are very fast storage inside the CPU。They reduce memory access and improve performance。

---

## 22. Kernel Mode and User Mode

### Definition

**Kernel mode** allows execution of privileged operations and direct hardware control。  
**User mode** restricts ordinary programs so they cannot directly access all hardware or kernel memory。

### Why this is protection

User programs cannot directly damage hardware, access other processes' memory, or modify kernel data。They must request OS services through system calls。

### Privileged instructions

Usually privileged：

- set value of timer；
- clear memory；
- turn off interrupts；
- modify device-status table；
- access I/O device directly；
- change memory-management structures。

Usually not privileged：

- read the clock；
- issue a trap instruction to request OS service。

### Consequence of allowing direct OS calls

If user programs could directly call arbitrary OS functions, they could bypass checks, corrupt kernel state, access protected resources, and compromise the system。

---

## 23. System Calls and Traps

### System call

A **system call** is the controlled interface through which a user program requests a service from the OS kernel.

Examples：open, read, write, close, fork, exec, wait。

### Trap

A **trap** is a software-generated interrupt caused by an error or a user request, often used to enter kernel mode for a system call。

### Kernel-user memory copying

Kernel and user memory are separated。Kernel code should use explicit copying mechanisms such as `copy_from_user()` and `copy_to_user()` rather than directly trusting user pointers。

---

## 24. Interrupts

### Definition

An **interrupt** is a signal from hardware or software that causes the CPU to stop normal execution and run an interrupt handler.

### Why interrupt handlers must be short

Interrupt handlers must finish quickly because they delay normal process execution and may block other interrupts。Long handlers reduce system responsiveness。

### Top half and bottom half

Device interrupt processing is split：

- **Top half** runs immediately in interrupt context, does urgent minimal work, and schedules later work。
- **Bottom half** does slower processing later, such as protocol handling and waking processes。

---

## 25. Process Context vs Interrupt Context

### Process context

Kernel code runs in **process context** when executing on behalf of a user process, usually during a system call。

Properties：

- may access user data using safe copying；
- may sleep/block if allowed；
- can be preempted by interrupts。

### Interrupt context

Kernel code runs in **interrupt context** while handling an interrupt。

Properties：

- must not sleep；
- should execute quickly；
- cannot safely access arbitrary user memory；
- used for device interrupt handling。

---

## 26. Kernel Modules and Device Drivers

### Kernel module

A **kernel module** is code that can be added to or removed from the running kernel, often used for device drivers。

Commands：

- `modprobe` inserts module；
- `rmmod` removes module；
- `lsmod` lists modules。

### Device driver

A **device driver** is kernel code that controls a hardware device and provides an interface to the rest of the OS/user programs。

User-space view often uses special files in `/dev` with system calls：

- `open`；
- `read`；
- `write`；
- `ioctl`；
- `close`。

### Why faulty drivers are dangerous

Drivers run in kernel mode and have direct access to hardware and kernel memory。A faulty driver can crash the whole system。

### Can drivers be made unable to crash the OS?

Traditional monolithic kernels cannot fully guarantee this if drivers run in kernel mode。A microkernel or user-space driver design can isolate faults better, but usually with performance/complexity costs。

# Part D - Processes and Scheduling

## 27. Process

### Definition

A **process** is a program in execution.

A process includes：

- program code / text；
- program counter；
- CPU registers；
- stack；
- heap；
- data section；
- OS resources。

---

## 28. Process States

### States to memorise

- **new**：process is being created。
- **ready**：process is waiting to be assigned to CPU。
- **running**：instructions are being executed。
- **waiting / blocked**：process is waiting for an event, such as I/O。
- **terminated**：process has finished execution。

### Transitions

- new -> ready：admitted。
- ready -> running：scheduler dispatch。
- running -> ready：preemption / time slice expired。
- running -> waiting：I/O or event wait。
- waiting -> ready：I/O or event completion。
- running -> terminated：exit。

---

## 29. Process Control Block (PCB)

### Definition

A **Process Control Block (PCB)** is a kernel data structure storing information needed to manage a process.

It may contain：

- process state；
- program counter；
- CPU registers；
- scheduling information；
- memory-management information；
- accounting information；
- I/O status information。

---

## 30. Context Switch

### Definition

A **context switch** is the operation of saving the state of one process/thread and restoring the state of another so the CPU can switch execution.

### Why it is expensive

It takes time to save/restore registers and scheduler state。It can also disturb cache/TLB contents, reducing performance after the switch。

---

## 31. Scheduling Queues

### Queues

- **Job queue**：all processes in the system。
- **Ready queue**：processes in memory ready to run。
- **Device queues**：processes waiting for I/O devices。

Processes move between these queues during execution。

---

## 32. CPU Scheduling

### Definition

**CPU scheduling** is the OS decision about which ready process should get the CPU next.

### Prerequisites / assumptions for scheduling algorithms

Scheduling algorithms usually assume：

- process behaviour can be estimated, such as CPU burst length or priority；
- context switching overhead is not too high；
- the scheduler can make decisions often enough；
- the system has meaningful goals such as throughput, response time, fairness, or deadline satisfaction。

---

## 33. Scheduling Criteria

Common criteria：

- **CPU utilisation**：keep CPU busy。
- **Throughput**：complete many jobs per time unit。
- **Turnaround time**：time from submission to completion。
- **Waiting time**：time spent in ready queue。
- **Response time**：time until first response；important for interactive systems。
- **Fairness**：avoid starvation。

---

## 34. FCFS - First Come First Served

### Idea

Processes run in arrival order。

### Advantages

- simple；
- no starvation in basic queue。

### Disadvantages

- can cause convoy effect；
- bad for interactive response if a long CPU-bound job arrives first。

### Exam use

FCFS is often unsuitable for mixed interactive/CPU-bound workloads requiring short response time。

---

## 35. SJF - Shortest Job First

### Idea

Run the process with the shortest expected CPU burst first。

### Advantages

- minimises average waiting time if burst lengths are known。

### Disadvantages

- hard to know future burst length；
- long jobs may starve。

---

## 36. Round Robin

### Idea

Each process gets a fixed time quantum in turn。

### Advantages

- good response time for interactive systems；
- fair sharing of CPU。

### Disadvantages

- too small quantum causes too many context switches；
- too large quantum becomes similar to FCFS；
- may be bad for continuous data devices if process is not scheduled often enough。

---

## 37. Priority Scheduling

### Idea

Run the process with the highest priority。

### Advantages

- useful when some tasks are more important or time-critical。

### Disadvantages

- low-priority processes may starve。

### Remedy for starvation

Use **aging**：gradually increase priority of waiting processes。

---

## 38. Multilevel Queue Scheduling

### Idea

Separate processes into different queues, often by type：interactive, batch, system, background。

Each queue may use a different scheduling algorithm。

### Exam use

Good for scenarios with different classes of work, such as interactive tasks needing low response time and background CPU-intensive jobs needing throughput。

---

## 39. Scheduling Scenario Templates

### I/O-bound vs CPU-bound

- **I/O-bound** processes often block waiting for I/O and use short CPU bursts。
- **CPU-bound** processes use long CPU bursts。

A scheduler favouring recent low CPU usage tends to favour I/O-bound programs but does not necessarily starve CPU-bound programs if priority changes over time。

### Maximise throughput with mixed jobs

For mixed computationally expensive previews and I/O-intensive purchases, choose a policy that prevents CPU-heavy jobs from blocking I/O-heavy jobs。Use priority or multilevel queues to keep I/O-bound tasks responsive and keep CPU utilised。

### Real-time / continuous data device

For CD-writer or continuous output device, scheduling must ensure process gets CPU often enough and memory pages are resident enough。Otherwise buffer underrun can occur。

---

# Part E - Memory Management

## 40. Logical vs Physical Address

### Definition

A **logical address** is the address seen by the program。A **physical address** is the actual address in hardware memory。

### Why needed

OS wants multiple programs in memory at the same time while protecting them from each other。Address translation maps logical addresses to physical addresses。

---

## 41. Virtual Memory

### Definition

**Virtual memory** gives each process the illusion of a large private address space, using disk as backing storage and loading pages into physical memory when needed。

### Benefits

- programs can be larger than physical memory；
- isolation between processes；
- easier memory allocation；
- only needed parts of a program must be loaded。

---

## 42. Swapping

### Definition

**Swapping** transfers memory of processes between main memory and disk when memory demand is too high。

### Problem

Swapping is slow because disk transfer time is large。Pending I/O also creates complications。

---

## 43. Fragmentation

### External fragmentation

Free memory exists, but is split into many small holes, so a large allocation cannot fit。

### Internal fragmentation

Allocated block is slightly larger than needed, wasting space inside the allocation。

### Allocation strategies

- **First-fit**：use first usable hole。
- **Rotating first fit**：start search after last allocation。
- **Best fit**：use smallest usable hole。
- **Buddy system**：use power-of-two block sizes, split and recombine buddies。

---

## 44. Paging

### Definition

**Paging** divides logical memory into fixed-size pages and physical memory into frames。Page table maps pages to frames。

### Benefits

- avoids external fragmentation；
- supports virtual memory；
- enables memory protection using page table bits。

### Page fault

A **page fault** occurs when a process accesses a page that is not currently in physical memory。The OS must load it from disk, which is much slower than normal memory access。

Important exam idea：even a small page fault rate can cause poor effective access time because disk access is extremely slow compared with memory。

---

## 45. TLB / Page Table Cache Idea

Page tables can be large and stored in memory。A **TLB** caches recently used page table entries to speed up address translation。

General principle：large lookup tables are accelerated using small fast caches for recently used entries。

---

## 46. Page Replacement

### FIFO

**FIFO** replaces the page that has been in memory longest。

Pros：simple。  
Cons：may remove heavily used pages。

### Optimal

**Optimal** replaces the page that will not be used for the longest time in the future。

Pros：best possible fault rate。  
Cons：not implementable in practice because future references are unknown。Useful as comparison benchmark。

---

## 47. Working Set Model

### Definition

The **working set** of a process is the set of pages it has used recently, usually within a fixed time window。

### Purpose

The OS tries to keep each process's working set in memory。If a process does not have enough frames for its working set, it will page fault frequently。

---

## 48. Thrashing

### Definition

**Thrashing** occurs when the system spends most of its time paging rather than executing useful instructions。

### Symptoms

- high paging disk utilisation；
- low useful CPU progress；
- poor response time；
- low throughput；
- adding more processes makes performance worse。

### Causes

- too many processes in memory；
- working sets do not fit in physical memory；
- memory-heavy applications increase pressure。

### Remedies

- decrease degree of multiprogramming；
- suspend/swap out some processes；
- use working set model；
- add memory if allowed；
- avoid running too many memory-intensive programs。

### Exam scenario answer

If CPU appears busy but throughput drops and response time becomes much worse after a memory-heavy IDE upgrade, a likely cause is thrashing。Remedy without hardware：reduce multiprogramming, run fewer background processes, or limit memory-heavy applications。

---

# Part F - File Systems and I/O

## 49. File System

### Definition

A **file system** organises permanent storage and maps the logical view of files/directories to physical disk blocks。

### Logical view

Users/programmers see a tree of directories and files with operations such as read, write, create, open, close。

### Physical view

Disk is a sequence of blocks/sectors。The OS must allocate blocks and record which blocks belong to which file。

---

## 50. Linked Allocation vs Indexed Allocation

### Linked allocation

Each file block points to the next block。

Advantage：simple, easy sequential access。  
Disadvantage：random access is slow because the system must follow the chain。

### Indexed allocation

Pointers to file blocks are stored in an index block。

In Unix-like systems, index blocks are **inodes**。

Advantages：better random access, stores metadata such as file size and permissions。  
Disadvantage：index structure overhead；large files may need indirect index blocks。

---

## 51. FAT

### Definition

**FAT** stands for File Allocation Table。It represents files using linked cluster chains stored in a table。

Important terms：

- **sector / block**：disk unit, e.g. 512 bytes；
- **cluster**：group of sectors；
- FAT entry points to next cluster in a file chain。

---

## 52. Open and Close System Calls

### Why open?

`open` checks permissions, locates the file, creates kernel data structures, and returns a file descriptor/handle for later operations。

### Why close?

`close` releases kernel resources, flushes pending data if necessary, and tells OS the process no longer needs the file。

---

## 53. Disk Scheduling and LOOK

### LOOK algorithm

**LOOK** disk scheduling moves the disk arm in one direction servicing requests until there are no more requests in that direction, then reverses direction。

Difference from SCAN：LOOK only goes as far as the last request, not all the way to the physical end of the disk。

Benefits：reduces unnecessary movement and gives more predictable service than FCFS。

---

## 54. DMA and Kernel Buffers

### Definition

**DMA (Direct Memory Access)** allows a device controller to transfer data directly between device and memory without CPU copying each byte。

### Why use kernel buffers?

Disk data is usually written into kernel buffers first because the kernel controls and validates memory access。Writing directly into user memory is difficult/dangerous because：

- user pages may not be resident；
- user memory mapping may change；
- permissions must be checked；
- device must not be allowed to overwrite arbitrary memory；
- kernel must handle I/O completion safely。

It may be possible with pinned/locked user pages and careful checks, but not as a simple direct write。

---

# Part G - Kernel Programming and Protection

## 55. Kernel Programming Risk

Kernel code has access to all resources and is not constrained like user programs。A bug in kernel code can crash the whole system, corrupt memory, or compromise security。

This is why kernel programming requires care with：

- memory leaks；
- invalid pointers；
- sleeping in interrupt context；
- race conditions；
- untrusted user pointers。

---

## 56. User-Kernel Separation

### Why not directly access user memory?

Kernel must not blindly dereference user pointers because user memory may be invalid, malicious, unmapped, or changed concurrently。Use controlled copying such as `copy_from_user()` and `copy_to_user()`。

Direct access could crash the kernel or create security vulnerabilities。

---

## 57. Privileged Operations - Exam Table

| Operation | Privileged? | Reason |
|---|---|---|
| Set timer | Yes | controls CPU preemption |
| Read clock | Usually no | harmless information |
| Clear memory | Yes | could destroy other processes/kernel |
| Trap instruction | No | needed for system calls |
| Turn off interrupts | Yes | could stop OS control |
| Modify device-status table | Yes | affects devices/kernel |
| Switch from user to kernel mode directly | Yes/controlled only | must happen only through trap/interrupt |
| Access I/O device directly | Yes | could corrupt devices/data |

# Part H - Multicore, Cache and Performance

## 58. Multicore Systems

### Definition

A **multicore system** has multiple CPU cores on one chip, allowing parallel execution。

### Shared and private resources

Often：

- each core has private L1 cache；
- some systems have private L2 cache；
- cores may share L3 cache；
- all cores share main memory。

### Synchronisation performance cost

Adding mutual exclusion can slow real-time performance because：

- threads wait for locks；
- critical sections serialize execution；
- cache coherence traffic increases；
- context switching / blocking overhead increases；
- too coarse-grained locks reduce parallelism。

---

## 59. Cache Efficiency

### Main idea

Programs are faster when they access memory in cache-friendly order。For row-major arrays in C, iterate along rows so consecutive memory locations are accessed。

For a matrix stored row-major, prefer：

```c
for (int i = 0; i < rows; i++)
    for (int j = 0; j < cols; j++)
        set(m, i, j, val);
```

This has better spatial locality than jumping between columns。

# Part J - Exam Scenario Answer Bank

## 1. Why did response time become bad after adding a memory-heavy IDE?

Likely cause：working sets no longer fit in memory, causing frequent page faults and thrashing。Even if CPU utilisation appears high, useful throughput drops because time is spent handling paging。Remedy：reduce degree of multiprogramming, suspend background jobs, limit memory-heavy programs, or add memory if allowed。

## 2. How to distinguish overloaded CPU, thrashing, and overused disk?

- Overloaded CPU：CPU utilisation high, paging disk not especially high。
- Thrashing：paging disk utilisation very high, response poor, throughput low。
- Overused disk：ordinary I/O disk high, paging disk not necessarily high；file operations slow。

## 3. Why does passing `&i` to many threads cause repeated values?

All threads receive the address of the same loop variable `i`。They may read it after the main thread has changed it。Because scheduling is nondeterministic, multiple threads may print the same final or intermediate value。Fix：give each thread a separate copy of the argument。

## 4. Why is a shared stack implementation unsafe?

Operations such as `push`, `pop`, and checking `count` access shared variables。Without a single lock protecting `count` and `values`, interleavings can corrupt the stack, lose updates, or read/write the wrong index。

## 5. Why are synchronisation bugs intermittent?

They depend on timing, scheduling, CPU speed, and interleavings。The same code may succeed many times and fail only rarely。

## 6. Why can a linked-list delete function crash?

If it frees a node and then accesses `node->next`, it uses memory after free。Correct approach：save `next` before `free`, then continue traversal。

## 7. Why are device-driver interrupts split into top and bottom halves?

Top half handles urgent work quickly in interrupt context。Bottom half performs slower processing later。This keeps interrupt latency low and system responsive。

## 8. Why are device drivers often installed with administrator privileges?

Drivers run in kernel mode and can access hardware/kernel memory。Installing them changes trusted kernel code, so administrator privileges are required for protection。

## 9. Why is Round Robin sometimes bad for continuous data output?

If time quantum/scheduling delay prevents the process from supplying data continuously, the device buffer may underflow。Virtual memory page faults can worsen delays。

## 10. Why is direct user access to I/O devices unsafe?

User programs could corrupt devices, bypass permissions, interfere with other processes, or compromise system integrity。The OS must mediate device access。

# Final Exam Writing Style

For definition questions：

> A **keyword** is ...

For explanation questions：

> This happens because ... The consequence is ... Therefore, the OS/programmer should ...

For scenario questions：

> The most likely cause is ... This is indicated by ... A suitable remedy is ... because ...

For comparison questions：

> Method A is good for ... but bad for ... Method B is better when ... Therefore, in this scenario I would choose ...

**Most important rule：** 不要只写名词。每个答案都要包含 definition + mechanism + consequence + remedy。
